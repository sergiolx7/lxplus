# LX Plus Premium — relatório de 30/10/2026

## Entrega

Reconstrução da interface, separação dos módulos e integração com o Supabase existente. O frontend utiliza dados reais por padrão. A fixture local de QA está isolada e excluída da publicação. Desenvolvido para a LX Group.

O trabalho tem uma base funcional publicada pelo pipeline do repositório, mas não representa homologação integral de todos os itens solicitados. Os limites abaixo fazem parte da entrega.

## Inventário e preservação

Foram examinadas a árvore principal anterior, a branch `lxplus-v40-completa` e a estrutura do banco existente. A nova árvore reaproveita Auth, catálogo, perfis, estado pessoal, amizade, mensagens, sinalização individual, ranking, suporte e administração do servidor. Recursos com UI antiga não recuperada estão identificados como pendentes.

Antes do arquivamento foi criado um snapshot privado de 89 tabelas, 87.752 linhas e 2.866 definições de estrutura. Contagens e checksums foram conferidos; cópias para tabelas temporárias foram comparadas. O arquivo privado está preservado separadamente. Essa validação não equivale à restauração integral em um projeto Supabase vazio. O backup não contém os bytes dos arquivos de Storage/Drive e não é um backup físico/PITR.

## Testes executados

- `npm test`: 34 testes passaram, além da verificação de sintaxe de todos os módulos. Cobrem fila, importação CSV/JSON, fontes duplicadas, limites, URLs maliciosas, HTML, UUID, home, dependências locais, persistência de Auth e resolução de mídia.
- `npm run build`: produz somente o frontend; SQL, backups, testes e fixture ficam fora. Módulos locais recebem a mesma versão de cache da entrada.
- `tests/rls-readonly.sql`: membro aprovado sem privilégio administrativo; mensagens, playlists privadas, versões e backup isolados; RPCs protegidas negadas ao anônimo.
- `tests/rls-crud-rollback.sql`: post privado, like/comentário, playlist, consentimento/expiração, autoria, negação administrativa, merge de estado, criação de rascunho e rejeição de fonte duplicada. Todas as gravações de teste foram revertidas.
- Browser local: tela real de entrada; no QA isolado, navegação, playlist, áudio nativo contínuo, DM e rascunho ADM. Layout móvel e acesso às conversas conferidos; largura do conteúdo sem transbordamento horizontal.
- Preservação: nova consulta após os testes confirmou 7 contas, zero removidas, zero senhas modificadas, zero perfis alterados e zero filmes/músicas antigos publicados.

Não foram feitos testes de carga para milhares de usuários, benchmark de escala, teste de desastre completo, teste de autenticação com credenciais do proprietário nem testes em Android, iPhone ou Safari real.

## Operação, publicação e reversão

O workflow do Pages executa testes e build antes de publicar `dist/`. O domínio original foi mantido. `dist/build.json` identifica a versão efetiva de cache.

O commit anterior é `e2a2516aab2047be5b585fcf20686b1ee090bc4c`, preservado na branch `backup/pre-premium-rebuild-20261030`. Também foi verificado um bundle completo do Git antes da reconstrução.

Para reverter a interface, publique novamente o commit anterior pelo fluxo normal do repositório, sem apagar a branch nova. As migrações são aditivas e não devem ser removidas automaticamente. Para devolver o catálogo antigo, um operador autorizado deve revisar e executar `ops/restore_catalog_archive.sql`: restaura payload e visibilidade originais apenas dos filmes/músicas marcados pela limpeza. Não execute todos os scripts de `ops/` em lote. O snapshot privado não está acessível às funções de usuário comum.

As migrações incluídas têm os mesmos identificadores do histórico remoto. O histórico anterior do banco e o snapshot de backup não foram reexportados como migrações públicas; por isso não se deve executar `supabase db push` cegamente contra um banco vazio. A função `lx-drive-studio` exige seu helper de `src/drive-import.js` no pacote de implantação.
